# Photography lead analysis contract

The unified `dave-blake.com` session tracker reached production in the site release on **2026-09-29 at 03:54 UTC** (PR #11, merge `8d102b5`). Sessions from that point use one tab-scoped ID and first-touch attribution across Digitals, portfolio and contact pages. Use **2026-09-30 UTC onward** for complete comparable daily windows.

Query `GET /api/stats` with `site=dave-blake.com`, a `range` of at most 90 days, `environment=production`, and `traffic=production` for business reporting. The existing `source_host` filter also applies. `traffic=test` includes flagged test journeys on the production host; `traffic=all` includes both. The five filters apply to every new field below.

The production slice requires the stored Analytics Engine environment (`blob17`) to be exactly `production`, as it did before this change. Empty legacy environments and other non-production values enter the test/non-production slice. An observed session with any event explicitly marked as test is classified as test throughout the event aggregates, including `events.byTestTraffic` and `behaviour`.

`events.verifiedLeads` counts only `db_contact_form_submit_success`. Its `total` and `byFirstTouchSource` counts are event counts; `byFirstTouchLandingPage` uses query-free paths, and `byFirstTouchUtmCampaign` uses the campaign value stored on the success event. Source, landing-path and campaign buckets are case-sensitive; campaign values are not shortened at query time. `observedSessions` counts distinct IDs seen with that success event. The older `events.leads` field has broader lead semantics and remains unchanged for existing consumers.

`events.ctaClicks` groups `db_cta_click` events by `ctaId`; it does not imply a later lead. `events.funnel.eventCounts` contains counts for CTA clicks, form views, form starts, validation errors, submit errors and verified leads. `events.funnel.observedSessionCounts` counts distinct observed sessions for the same steps; `events.funnel.observedSessions` counts all observed event sessions in the filtered range. Repeated events in one session count once in session fields.

Analytics Engine stores each event's name, date, source host and environment as dimensions, plus a bounded JSON event context in `blob20`. Session ID, first-touch source, first-touch landing path, UTM campaign and CTA ID are queryable through that context, but are not separate SQL grouping dimensions. The Worker aggregates these in memory and returns no session IDs or raw journeys. Older truncated or malformed contexts are grouped as `unknown` or `none` when appropriate; historical query strings are stripped from reported landing paths.

When a context exceeds 1,500 serialized characters, compaction reserves space for every present critical field before retaining optional context. Its per-field maximum is measured in JSON-encoded value characters, including escapes: `session_id` 128; `is_test_traffic` 5; `source_env` 16; `event_ts_client` 40; `page_path` 160; `first_touch_source` 84; `first_touch_landing_page` 160; `first_touch_utm_source` 64; `first_touch_utm_medium` 48; `first_touch_utm_campaign` 160; `cta_id` 80; `funnel_step` 24; `pathway` 24; `error_type` 48; `error_class` 24; `field_name` 48; `http_status` 4. Longer values are shortened only in compacted contexts; the context carries `truncated: true`. The site tracker itself limits campaign names to 160 characters. Attribution questions involving long or escaped values should account for possible compaction shortening.

Analytics Engine may sample events: event counts use sampling weights and can be estimates, while session counts are observed IDs and are not scaled into invented visitors. A source, landing path or campaign breakdown describes the verified success **event's stored first-touch context**, not an inferred join to an earlier page view. CTA-to-lead session attribution is deferred because sampled rows can omit one side of the relationship. A form success is a verified analytics lead, not proof of a paid booking; reconcile with actual enquiries for business outcomes. Production-host test sessions are excluded from new production event aggregates when their stored test flag is present. Older production-host events without that flag cannot be classified retrospectively.

The existing live `behaviour` response remains available for the site reporting script. It describes observed sessions, ordered model-form steps, first-touch landing pages and sources, pathways, form errors, and click transitions, with sampling and missing-data quality fields. Historical camelCase timestamps, paths, attribution and error fields are resolved when reading stored events. Transitions use the stored envelope source path when custom page-path context is absent, and configured internal hosts share route buckets. Its session counts are observed rows, not complete unique visitor estimates. This implementation was recovered from the older outbound-click-tracker checkout's uncommitted `src/behaviour-insights.ts` and `src/worker.ts` work; the live production response already exposed the same field before this PR.
